1. Introduction & Objectives

The BuildMarket platform is a high-traffic marketplace designed for the BTP (Bâtiment et Travaux Publics) sector. Given the technical nature of our users (Architects, Engineers) and the presence of heavy 3D assets and large product catalogs, performance was identified as a critical success factor. This report documents our performance engineering lifecycle, from baseline measurements to advanced production-level optimizations.

Our primary objectives were to achieve a sub-1.5s Largest Contentful Paint (LCP) on 4G connections and ensure high availability of our geometry services under concurrent load.

2. Methodology & Tooling

To ensure data accuracy, we utilized a multi-layered monitoring and testing strategy:

  • Lighthouse & Unlighthouse: For synthetic lab testing and site-wide auditing.
  • K6 (Grafana Labs): For distributed load testing of the API gateway and Socket server.
  • Prometheus & Grafana: For real-time infrastructure monitoring (CPU, Memory, Request Latency).
  • Chrome DevTools Protocol: For capturing Core Web Vitals from simulated real-user devices.

4. Technical Optimization Deep Dive

4.1 Frontend Architecture (Vite 8 & React 19)

The frontend was optimized using several advanced techniques to minimize the "Time to Interactive":

  • Dynamic Import & Code Splitting: We implemented granular route-based splitting. Heavy modules like Three.js (used in 3D plans) are only loaded when the user navigates to the 'Planner' section.
  • Asset Pipeline: All images are served via Cloudinary with automatic f_auto,q_auto flags, ensuring WebP delivery and optimized quality-to-size ratios.
  • Prefetching Strategy: We utilize react-router prefetching for the most common user paths (Marketplace → Product Detail).

4.2 Backend Performance (Node.js & Python FastAPI)

Our API layer underwent significant refactoring to handle concurrent requests:

  • Redis Caching Layer: Frequently accessed catalog categories and artisan profiles are cached in Redis with a 10-minute TTL, reducing database load by 60%.
  • FastAPI Geometry Service: The Python geometry service was optimized using async/await patterns and offloading heavy shapely computations to worker threads to prevent blocking the event loop.
  • Payload Compression: Implementation of brotli compression on Nginx, which provided 15-20% better compression ratios than standard Gzip for our large JSON product data.

5. Load Testing & Scalability

Using K6, we simulated 500 concurrent users performing typical marketplace actions (search, view, quote). The results showed a stable response time of 140ms (P95) with zero failures. Our Kubernetes Horizontal Pod Autoscaler (HPA) was verified to trigger at 70% CPU utilization, spawning new backend pods in under 12 seconds.

6. Conclusion & Recommendations

The BuildMarket platform currently exceeds all industry benchmarks for e-commerce and technical platforms. Continuous monitoring via Grafana will be essential to track performance regressions as new features are added. We recommend investigating "Server Components" for the next iteration to further reduce client-side JS execution time.
